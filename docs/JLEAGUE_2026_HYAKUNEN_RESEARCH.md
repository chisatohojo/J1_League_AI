# 2026年 明治安田J1百年構想リーグ 調査報告

調査日: 2026-09-14、実装・最終検証日: 2026-09-15（日本時間）。中断前の調査と原本を保持して実装を完了した。
通常の2026/27 J1の試合結果は取得していない。

## 結論

全200試合を取得できた。地域リーグラウンド180試合とプレーオフ20試合を区別する必要がある。
地域のPK戦は51試合、プレーオフの延長は1試合、プレーオフのPK戦は0試合だった。
**一覧のスコアを常に90分得点として保存してはいけない。**
町田－名古屋（33017）は一覧では2-1だが、詳細では90分0-0、延長2-1である。

地域180試合とプレーオフ第1戦10試合は大会規則上延長がなく、一覧から90分得点を取り出せる。
延長が起こり得るプレーオフ第2戦は全10詳細を保存・照合したため、今回の全200試合は90分得点を復元できる。
ただし、プレーオフPK戦の実例はなく、HTMLの取得可能性は実データでは未実証。人工fixtureで解析・勝者判定を検証した。
既存2015～2025年の形式・共通処理・Validationには変更を加えず、別大会の正規化・構造検証・成果物生成を実装した。

## 公式大会方式と実データ

[公式大会実施要項](https://aboutj.jleague.jp/corporate/assets/pdf/regulation/jleague/myjleague_100year_vision_league_match_regulations_revision.pdf)
の第7条・第18～21条と、[公式プレーオフ対戦カード発表](https://www.jleague.jp/news/article/33954/)を確認した。
20クラブをEAST/WEST各10クラブに分け、地域内ホーム＆アウェイ2回戦総当たりの後、
両グループの同順位同士でホーム＆アウェイの順位決定戦を行う。

| 項目 | EAST | WEST | プレーオフ | 大会全体 |
| --- | --- | --- | --- | --- |
| クラブ数 | 10 | 10 | 20 | 20 |
| 構造 | 18節・各5試合 | 18節・各5試合 | 10カード・各2試合 | 地域＋プレーオフ |
| 期待／実試合数 | 90／90 | 90／90 | 20／20 | 200／200 |
| 各クラブ試合数 | 18 | 18 | 2 | 20 |
| 各クラブhome／away | 9／9 | 9／9 | 1／1 | 10／10 |
| 開催期間 | 02-06～05-24 | 02-06～05-24 | 05-30～06-06 | 2026-02-06～06-06 |
| PK戦 | 22 | 29 | 0 | 51 |
| 延長戦 | 0 | 0 | 1 | 1 |
| 90分結果 Away／Draw／Home | 30／22／38 | 27／29／34 | 8／7／5 | 65／58／77 |

期待件数は `2 × (10 × 9 / 2 × 2) + 10 × 2 = 200`、
各クラブは `2 × (10 - 1) + 2 = 20` と公式方式から導出できる。
通常の20クラブ・38節・380試合の設定は適用できない。

地域ラウンドは90分（アディショナルタイムを含む）で同点の場合、延長なしでPK戦。
勝点は90分勝利3、PK勝利2、PK敗戦1、90分敗戦0。
プレーオフ第1戦には引分があり、第2戦終了時に2試合の勝利数、得失点差の順で順位を決める。
決まらなければ30分の延長、PK戦、なお決まらない場合は抽選。アウェイゴール優先はない。
規則上のみなし開催の例外では延長・PKを行わない場合もあるため、将来の処理で一律に補完しない。

第1戦はWESTホーム、第2戦はEASTホームで、実データの全10カードも一致した。
地域内の45対戦カードについて正逆各1試合、プレーオフ10カードについても正逆各1試合を確認した。

## HTML構造と既存解析との差分

結果表は従来と同じ`table.table-base00.search-table`が1個、ヘッダーを除いて200行。
列は次の11列で、従来の並びと同じ。

```text

スタジアム, 入場者数, インターネット中継・TV放送
```

| 項目 | 今回の原表記／構造 | 既存形式との差分 |
| --- | --- | --- |
| シーズン | `2026特別` | 整数年の表記ではない |
| 大会 | `明治安田Ｊ１百年構想 EASTグループ`、`WESTグループ`、`プレーオフラウンド` | 通年の`Ｊ１`とは異なる |
| 地域の節 | `第１節第１日`等、第1～18節 | EAST/WESTの区別が必要 |
| プレーオフ | `第１戦第１日`8件、`第１戦第２日`2件、`第２戦第１日`10件 | 「節」ではなく「戦」＝leg |
| スコア | `h-a`または`h-a<br />(PKp-q)` | PKが追加。プレーオフではh-aに延長得点を含む場合がある |
| ID | スコアのa要素の`match_card_id` | 取得方法は同じ。非連続IDを保持する |
| 日付・時刻・会場 | 表示日付、K/O時刻、会場略称 | 従来と同じ位置から取得可能 |
| 順位決定枠 | 放送列の`１‐２位決定戦／ＤＡＺＮ`等 | 放送列を丸ごと捨てると順位決定枠を失う |

詳細は`div.score-board-main`内の`th#team-name-l`／`th#team-name-r`がホーム／アウェイ、
`td.score`が各チームの表示得点、`td.time`内の`dl`が期間別得点。
`dt`に「前半」「後半」「延長前半」「延長後半」、左右の`dd.left-area`／`dd.right-area`に得点がある。
詳細の正式クラブ名と一覧の略称は区別して保持し、独自の名称変換で上書きしない。
一覧と詳細の両側にある公式クラブprofile URLを照合し、名称の略称／正式名に依存せずホーム／アウェイの対応を確認する。

PKの合計は`div.score-board-pk`内の`th`が「PK戦」の表で左右の得点を確認できた。
ただし同じclassは得点者の表にも使われ、PKの各キック明細にも「PK戦」が出る。
classの存在だけでPK実施を判断せず、表の見出しと左右の数値を組み合わせて識別する必要がある。

## 採用した追加モデル

通常リーグとは別の大会キー`j1_hyakunen_2026`で管理する。
既存の`SEASON_FORMATS`へ2026年の`full_season`を足す方法は採らない。
保存先は`data/processed/jleague/2026_hyakunen/`とし、既存年別CSVから分離した。
`matches.csv`は200行・48列、`playoff_ties.csv`は10行・18列。nullはCSVでは空欄、JSONではnullで保存する。

| 情報 | 保存する項目 | 意味・適用範囲 |
| --- | --- | --- |
| 大会識別 | `competition_key`, `season`, `source_year_id`, `source_season_label`, `source_frame_id` | キー、暦年2026、選択肢20261、2026特別、大会枠35を区別 |
| 試合識別・来歴 | `match_id`, `source_url`, `detail_source_url`, `score_90_source` | 公式IDと90分内訳の根拠を追跡。原本SHA等はsummaryのacquisitionに保存 |
| 進行区分 | `stage`, `group`, `home_group`, `away_group` | regional／playoff。groupは地域のみEAST／WEST。POのgroupはnull |
| 節・戦 | `round`, `leg`, `round_label` | roundは地域1～18、legはPO1／2。適用外はnull、原表記を保持 |
| 対戦基本情報 | `match_date`, `match_date_label`, `kickoff_time`, `home_team`, `away_team`, `stadium` | 現在の原表記と意味を保持 |
| チーム識別 | `home_team_source_url`, `away_team_source_url`, `home_team_detail`, `away_team_detail` | 公式profile URLで左右照合。取得済み詳細の正式名も保持 |
| 原表示 | `raw_score_text`, `displayed_home_score`, `displayed_away_score`, `broadcast_raw` | 延長込みの場合がある得点、PK文字列、順位決定枠の根拠を保存 |
| 90分 | `home_score`, `away_score`, `result` | 0=Away、1=Draw、2=Home。PK・延長を得点やresultに混ぜない |
| 延長 | `extra_time_played`, `home_extra_time_score`, `away_extra_time_score` | 増分だけ。90分得点＋延長得点＝表示得点を照合 |
| PK | `pk_played`, `home_pk_score`, `away_pk_score`, `pk_scope`, `pk_winner_team` | scopeは地域match／PO tie。未実施と未確認を区別 |
| 単一試合の勝敗 | `match_winner_team`, `match_decision` | 地域はPKまで反映。POは90分＋延長の得点比較。drawは勝者null |
| 地域の勝点 | `home_points`, `away_points` | 地域のみ3/2/1/0。POはnull |
| 順位決定 | `playoff_tie_id`, `placement_range` | PO2試合を結び、放送列の順位決定枠を保持 |

プレーオフの勝者は別の順位決定カード表に`tie_winner_team`・`tie_decision`・2試合のID・確定日を置く。
`east_team`／`west_team`を基準に、`east_score_90`／`west_score_90`に90分の2戦合計、
`east_total_score`／`west_total_score`に延長込み2戦合計、`east_wins_90`／`west_wins_90`に90分勝利数を保持する。
`first_match_id`／`second_match_id`・各試合日・`confirmed_date`を収録し、PK得点は第2戦の試合行から参照する。
第2戦の勝者をそのままカード勝者にせず、公式の勝利数→得失点差→延長→PKの順序で判定する。
第1戦の行へ未来に確定する勝者を試合前情報として埋め込まない。
延長・PK未実施の得点はnull、実施した0得点は0とし、取得不足による未確認とも区別する。
必要な詳細が取得不足なら処理を停止し、未確認のまま正規化済み成果物を生成しない。

`match_decision`はregulation／extra_time／penalties／draw。
POではPKが行われても単一試合の得点比較による勝者を上書きしない。
`tie_decision`はregulation_wins／regulation_goal_difference／extra_time／penalties。
抽選・みなし開催など今回の原本で確認していない決着は推測で補完せず、未対応として停止する。

既存matches.csvの`home_score`・`away_score`・`result`へ将来投影するなら、90分値のみを対応させる。
ただし既存`round`は正の整数を必須としており、POのlegを便宜的にroundへ代入して通すべきではない。
別大会の正規化・検証を実装済み。既存形式への投影範囲と節番号の扱いは別途決定する。
既存Validationの必須条件を緩めたり、全200試合を既存CSVへ混在させたりする変更は行わない。

既存の共通表読取を再利用し、特殊なスコア・進行区分の解釈とmetadata照合は別アダプターへ置いた。
不足した詳細から90分結果を推測せず停止する。地域の総当たりとPOの2戦制は別の構造検証とする。
実例の地域PK・PO延長・第2戦とカード勝者の相違に加え、実例のないPO PKを人工fixtureで検証した。
