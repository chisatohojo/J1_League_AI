# J.League Data Site: 2022・2023年J1の共通取得・検証

調査・検証日: 2026-09-14（日本時間）。新規取得は2022・2023年J1リーグ戦のみ。
2015～2021年は保存済みキャッシュと出力を比較・回帰検証に再利用した。

## 結論と大会方式

両年とも18クラブのホーム＆アウェイ2回戦総当たり、34節・306試合。
公式の [2022年大会方式](https://www.jleague.jp/news/article/21360/) と
[2023年大会方式](https://www.jleague.jp/news/article/24237/?mode=pc)で確認した。
2021年の20クラブから2022年は18クラブへ戻るが、既存の大会構造設定で扱える。

`SEASON_FORMATS` に両年の18クラブ・`full_season`・総当たり2回を追加し、
`COMPARISON_SEASONS` に2022→2021、2023→2022を追加した。
共通HTML解析・キャッシュ読取・集計・CSV Validationの処理本体は変更していない。
年度専用関数・スクリプト・依存パッケージの追加も不要だった。

HTMLの表・11列・IDリンクは既存年度と同じで、既存15列へ情報を保持して正規化できた。
全612試合が既存Validationを通過。各年度のCSV・集計JSON・人間レビューを生成した。
2024年以降の取得、commit・pushは行っていない。

期待値は公式確認済み `N=18` と対戦回数2から導出する。
節数は `(N-1)×2`、各節 `N/2`、年間 `N×(N-1)`、各クラブhome/away各 `N-1`。
取得件数や観測クラブ数を基準に期待値を縮めない。stage・round・クラブ数・対戦網羅性を自動照合する。
2015～2023年の全9年度でも2,828件のmatch_idが一意で、年度間の重複はない。

## 取得・キャッシュ・来歴

両年ともHTML・metadataが未保存だったため、年度一覧に各GET 1回、合計2回だけアクセスした。
取得の間隔は2秒。詳細試合ページ、ステージ別ページ、付随ファイル、robots.txtは取得していない。
大会方式は上記の公式発表を参照し、取得後の解析・検証・再生成は通信なしで実施した。

| 年度 | 取得URL | 原本 |
| --- | --- | --- |
| 2022 | [2022年J1一覧](https://data.j-league.or.jp/SFMS01/search?competition_frame_ids=1&competition_years=2022&tv_relay_station_name=) | `data/raw/jleague/2022_j1_search.html` |
| 2023 | [2023年J1一覧](https://data.j-league.or.jp/SFMS01/search?competition_frame_ids=1&competition_years=2023&tv_relay_station_name=) | `data/raw/jleague/2023_j1_search.html` |

全件HTTP 200、`Content-Type: text/html;charset=UTF-8`、要求URLと最終URLは同一。
原本を応答バイト列のまま保存し、同名 `.metadata.json` にURL・status・UTC取得日時・bytes・SHA等を記録。

| 年度 | UTC取得日時 | bytes | SHA-256 |
| --- | --- | --- | --- |
| 2022 | `2026-09-14T03:56:03.106195+00:00` | 367,492 | `0eaca2d845798ff0ebd1630aae17765464793a989e19f7c69c2f4331ce4fe4a6` |
| 2023 | `2026-09-14T03:56:05.470906+00:00` | 368,119 | `e0c585a2a132c6897a286924b4569e68627e5c24ec5f973c0c13aaf3f801b1ce` |

キャッシュ読取時にURL・HTTP status・バイト数・SHA・取得日時の存在を照合する既存方針を維持した。
共通CLIにネットワーク取得機能はなく、不備・来歴不一致なら停止する。原本・metadataは編集しない。
取得データとprocessed成果物は既存 `.gitignore` に従うローカル保存で、Git管理対象には追加していない。

## HTML構造・既存年度との差分

| 項目 | 確認結果 |
| --- | --- |
| table / selector | 各原本に `table.table-base00.search-table` が1個。既存の `search-table` 選択で取得可能 |
| 行・列 | ヘッダー1行＋データ306行、各行11列。列名・順序は既存年度と同一 |
| HTML形式 | サーバー応答に全試合の行を含む。JavaScript実行・追加ページ不要 |
| 大会 | 原表記 `Ｊ１`。1st/2nd分割なし、解析上はfull_season |
| round / 日付 | `第n節第m日` と `YY/MM/DD(曜日・祝日)` の既存構文を使用 |
| スコア・K/O | 整数同士のハイフン区切り、時刻HH:MM。両年とも既存処理で解釈可能 |
| ID / source URL | スコアセルの `/SFMS02/?match_card_id=数字` から取得。詳細ページへの通信不要 |
| 正規化列 | 必須10列＋stage・competition・round_label・kickoff_time・source_urlの既存15列 |
| 欠損・注記 | 正規化15列に欠損・空白なし。原本11列にも空欄なし。放送欄に開催変更等の注記なし |

2021→2022年は共通16クラブ。追加は京都・磐田、外れた表記は仙台・大分・徳島・横浜FC。
2022→2023年も共通16クラブで、新潟・横浜FCが加わり、清水・磐田が外れる。
共通クラブの表記は一致し、全角文字を含むチーム名を独自変換していない。

2022年の会場表記は2021年比でエコパ・サンガＳ・ヤマハ・国立が加わり、
ヤンマー・ユアスタ・昭和電ド・浦和駒場・神戸ユ・鳴門大塚が外れる。
2023年は2022年比でデンカＳ・浦和駒場・長良川が加わり、アイスタ・エコパ・ヤマハが外れる。
これらは使用会場の集合の差分であり、名称変更・同一会場を自動判定したものではない。
クラブごとのホーム会場差分は各年の集計JSON・人間レビューに保存した。

## 特殊な日程と扱い

両年とも原本は開催日順で日付逆行0件だが、節番号が戻る箇所は2022年9、2023年4。
節番号を試合順序の代用にせず、原本の実施日・round・round_label・K/O・行順を保持する。

| 年度 | 原本で確認した例 |
| --- | --- |
| 2022 | 第9節のID27400/27401が02-23、第2節FC東京対名古屋（27342）が04-20 |
| 2022 | 第25節のID27546/27547が10-12。同節の開催範囲は08-13～10-12の60日間 |
| 2023 | 第11節浦和対広島（28260）が05-31、第12節浦和対湘南（28270）が06-28 |
| 2023 | 第16節神戸対川崎Ｆ（28298）が07-22。同節の開催範囲は06-03～07-22の49日間 |

原本放送欄に延期等の原因注記はなく、原因は断定しない。追加の年度専用分岐や日程補正は不要。
2023年最終行は12-03・名古屋対柏（28464）・長良川・K/O 14:48で、この時刻も原本どおり保持する。
各年内のIDは連続しているが、日付順とID順は一致しないため並べ替えない。
大得点の2022年08-27柏3-6 FC東京（27565）、2023年06-03柏4-5札幌（28304）も正常に扱える。
両年とも入場者0・非数値入場者・未確定スコアはなく、曜日と節内の第n日にも矛盾はなかった。
入場者・放送情報は従来どおり原本に保持し、CSV列は追加していない。
