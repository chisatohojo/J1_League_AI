## Objective

The experiment asks one fixed question on future, previously unplayed ordinary-J1 matches:

> Does adding the four frozen rolling xG means improve three-class probability forecasts beyond an Elo-only model trained on exactly the same recent rows?

The protocol also compares the operational XG Challenger, including its fixed fallback behavior, with the existing frozen Operational Champion. These are separate comparisons and must not be conflated.

## Model roles

### Model A — Operational Champion

Model A is the existing frozen Elo-only Logistic model. Its historical feature, training protocol, Elo parameters, preprocessing, and estimator are not changed by this document. It remains the operational reference and supplies fallback probabilities when X1 cannot consume xG.

### Model X0 — matched-sample Elo baseline

X0 is a new analysis comparator fitted on exactly the same 594 rows as X1.

Its only feature, in this order, is:

1. `elo_diff`

X0 separates the effect of the recent matched training population from the incremental effect of xG. X0 does not replace Model A operationally.

### Model X1 — XG Challenger branch

X1 is fitted on the same 594 row identities and targets as X0. Its features, in fixed order, are:

1. `elo_diff`
2. `home_last5_xg_for`
3. `home_last5_xg_against`
4. `away_last5_xg_for`
5. `away_last5_xg_against`

No availability flag, history count, xG difference, shots, shots on target, finishing deviation, Domestic Rest, player workload, suspension, lineup, or other feature enters either fitted model.

## Training population

X0 and X1 use every match satisfying all of the following:

- completed before the rolling feature freeze boundary;
- present in the validated 660-row rolling xG dataset;
- `xg_pair_available=true`;
- valid pre-match `elo_diff` under the existing project chronology;
- valid 90-minute three-class target.

The fixed population is:

| Competition | Training rows |
|---|---:|
| 2025 ordinary J1 | 328 |
| 2026 J1 100 Year Vision League | 186 |
| 2026/27 ordinary J1 opened first 80 | 80 |
| **Total** | **594** |

The exact 594 `match_id` values, not merely these counts, define the training set. A later artifact task must persist the sorted identity manifest and its SHA-256 before fitting. Any missing, extra, duplicate, or differently ordered identity is a hard failure.

No performance statistic may be calculated on these rows for feature or model selection. The 2025 and first-80 outcomes are opened data used only as fixed fitting observations after the specification was selected independently of their xG-model performance.

### Hyakunen training clarification

The earlier rolling-feature document treated the 100 Year Vision rows as history observations and did not authorize model fitting. This training freeze now explicitly authorizes the **186 pair-available Hyakunen rows for X0/X1 fitting only**, using their regulation-time labels. It does not add those rows to Model A's historical Logistic training and does not change Model A. This paragraph is the controlling rule for the X0/X1 training population.

## Elo feature chronology

`elo_diff` is generated by the existing frozen Elo policy:

- initial rating `1500`;
- `K=30`;
- home advantage `175` inside expected-score calculation only;
- feature value `home_rating - away_rating`, without adding home advantage;
- regulation-time result only;
- no PK or extra-time winner substitution.

The state proceeds chronologically through ordinary J1, the 100 Year Vision League, and completed 2026/27 ordinary J1 matches. Same-date matches use a common start-of-date Elo state and are updated only after all predictions for that date have been recorded.

Future completed results may update Elo state for later targets. That state update is feature generation, not Logistic retraining.

## Target semantics

The fixed class order is:

| Class | Meaning |
|---:|---|
| `0` | Away win |
| `1` | Draw |
| `2` | Home win |

Targets always represent the 90-minute regulation result. A PK winner, extra-time winner, placement winner, or two-leg winner must not replace the regulation result.

Hyakunen match `33017` is a valid training target row because its pre-match features and regulation result are valid. Its own official-final xG remains excluded from all later rolling xG history under `rolling_xg_v1`.

## Estimator and preprocessing

X0 and X1 each use an independent pipeline of:

```python
StandardScaler()
LogisticRegression(
    C=1,
    solver="lbfgs",
    max_iter=1000,
    random_state=0,
)
```

The fit is three-class multinomial Logistic behavior with `classes_ == [0, 1, 2]`. Class weights, sample weights, thresholds, probability multipliers, calibration, interaction terms, regularization search, and any alternate solver are prohibited.

Each scaler is fitted once on its own feature matrix from the fixed 594 rows. Prospective features or outcomes never enter scaler fitting. X0 and X1 share row identities and targets but have separate scaler dimensions and separate Logistic coefficients.

## One-time coefficient freeze

In the later artifact task:

1. Validate the exact 594-row identity manifest and feature schema.
2. Fit X0 once.
3. Fit X1 once.
4. Verify class order and finite probability output without calculating performance metrics.
5. Persist immutable artifacts and hashes.
6. Never refit either pipeline using any of the future 300 outcomes.

The coefficients, intercepts, scaler means, scaler scales, feature order, and training identities become immutable after that one fit. Future data corrections that would alter a training row must stop prospective operation and be documented; they do not silently trigger a refit.

## Rolling feature-state updates

Model weights are frozen, but point-in-time feature state continues to evolve.

For each future target date:

- generate xG features from eligible official xG observations strictly before that date;
- generate Elo from regulation results strictly before that date;
- generate all same-date predictions from the common start-of-date state;
- after the entire date is complete, append eligible same-date xG and update Elo for later dates;
- never use a target's own xG, result, or another same-date match as pre-match history.

The unresolved-scope exclusion for match `33017`, five-match window, no-reset competition continuity, equal competition weight, no imputation, and home/away-combined history remain unchanged.

## Missing xG and operational fallback

For a prospective target:

- if `xg_pair_available=true`, generate X0 and X1 branch predictions;
- if `xg_pair_available=false`, do not impute or invoke the fitted X1 branch;
- the operational X1 prediction is then exactly Model A's stored probability vector and class prediction.

There is no blending between A and X1. The record must identify whether its probability source is `X1` or `MODEL_A_FALLBACK`.

X0 exists only for the matched eligible comparison and is evaluated on the same `xg_pair_available=true` target rows as the X1 branch. X0 has no operational fallback role.

## Prospective evaluation boundary

The evaluation pool is fixed by the rolling-feature freeze timestamp:

```text
2026-09-22T07:16:21+09:00
```

It consists of the **300 2026/27 ordinary-J1 fixtures that were future at that timestamp**. The first 80 completed matches are fitting/history data, not prospective targets. Target membership is based on official fixture identity and freeze-time status, not merely a round label.

Before any prediction implementation, an append-only target manifest must store the 300 official match identities, freeze-time status, scheduled kickoff, and source snapshot/hash without results. Rescheduling may change the chronological prediction time but not target membership. An officially cancelled match with no completed result is documented and excluded without replacement.

The final prospective judgement is made after the fixed pool completes. Intermediate metrics may be produced only for operational monitoring and must not change features, coefficients, thresholds, fallback behavior, or data eligibility.

## Prediction operation and immutable records

Predictions must be generated and persisted before official kickoff. Same-date fixtures are produced as one batch from their shared start-of-date feature state. A successful write is append-only; an existing prediction row is never overwritten.

The minimum record schema is:

| Field | Meaning |
|---|---|
| `prediction_id` | Immutable unique record ID |
| `match_id`, `match_date`, `scheduled_kickoff` | Official target identity and timing |
| `model_role` | `A`, `X0`, or `X1_OPERATIONAL` |
| `prediction_source` | `MODEL_A`, `X0`, `X1`, or `MODEL_A_FALLBACK` |
| `model_version` | Immutable artifact version |
| `artifact_sha256` | Exact persisted model artifact identity |
| `feature_spec_version` | `rolling_xg_v1` |
| `protocol_version` | `xg_challenger_freeze_v1` |
| `training_cutoff` | `2026-09-22T07:16:21+09:00` |
| `xg_pair_available` | Point-in-time routing flag |
| `p_away`, `p_draw`, `p_home` | Probabilities in class order `0,1,2` |
| `predicted_class` | Argmax class in `0,1,2` |
| `prediction_generated_at` | Timezone-aware pre-kickoff timestamp |
| `feature_snapshot_sha256` | Exact point-in-time feature input identity |
| `fallback_applied` | True only for X1 operational fallback |
| `supersedes_prediction_id` | Null normally; explicit append-only correction link if operational evidence requires one |

Probabilities must be finite, within `[0,1]`, and sum to one within numerical tolerance. Actual score and `actual_class` are joined only after result confirmation into a separate evaluation view; they are not fields required to create a pre-match prediction.

If a genuine pre-kickoff data correction requires another record, the original remains immutable and the new record points to it through `supersedes_prediction_id`. Outcome knowledge must never trigger prediction replacement.

## Evaluation metrics

After outcomes are officially confirmed, use:

1. **Primary:** multiclass Log Loss.
2. **Secondary:** project-standard multiclass Brier score:

   ```text
   mean_over_matches(sum_over_classes((p_k - y_k)^2))
   ```

   Uniform three-class predictions therefore score `2/3`.
3. **Descriptive:** argmax Accuracy.

Class order must remain Away, Draw, Home (`0,1,2`) for probabilities, one-hot targets, confusion matrices, and metrics.

No metric from the 594 training rows is authorized for selection or reporting in the fit task.

## Comparison interpretation

### Primary incremental comparison

Compare **X1 branch vs X0** only on the identical prospective targets where `xg_pair_available=true`. This is the primary estimate of the incremental value of the four rolling xG features under a matched training sample.

### Operational comparison

Compare **X1 operational vs Model A** over the full completed prospective pool. X1 operational means X1 on eligible rows and exact A fallback on ineligible rows. This measures deployment behavior, not the isolated xG effect.

Model A and X0 use different training populations. Therefore A vs X1 alone must never be described as proof that xG helped or hurt. X0 vs A on eligible rows may be reported as a training-sample diagnostic, not as the primary feature conclusion.

Reports must always include eligible/fallback counts so metric denominators are explicit.

## Leakage safeguards

- The 594 training IDs are frozen before fitting.
- The prospective 300 target identities are frozen before outcomes.
- Scalers and models see training rows only.
- Future target outcomes never update model coefficients.
- Target and same-date xG never enter pre-match features.
- Elo uses only prior-date regulation results and same-date batching.
- Result fields are joined only after immutable predictions exist.
- Feature-state updates and model retraining are separate operations; only the former is allowed prospectively.
- 2025 and the opened first 80 cannot be used for model/feature selection or performance-based revision.

## Prohibited adaptive changes

After this freeze, the following are prohibited within this prospective cycle:

- changing the five-match window or competition weights;
- adding/removing/reordering features;
- xG imputation, clipping, transformation, or venue split;
- changing Elo `K`, home advantage, or replay scope;
- changing `C`, solver, iterations, random seed, class weights, or model family;
- draw thresholds, calibration, probability uplift, or blending;
- online or periodic retraining;
- replacing X0's row population;
- changing fallback from exact Model A probabilities;
- excluding targets in response to prediction difficulty or outcomes.

Any materially new data source or hypothesis belongs to a separate, prospectively frozen research cycle.
